# 카공맵 — 1단계 범위 결정서

- 작성일: 2026-08-15
- 상태: 확정 (열린 질문 7건은 아래 5장 참고)
- 근거: 사전 시장 조사 리서치 (`docs/research-summary.md` 참조)

---

## 1. 배경 요약

리서치의 결론은 명확했다.

- 수요와 정보 공백은 실재한다 (대학생 87.0% 카공 경험, 네이버/카카오에 콘센트·소음·카공 정책 필터 없음).
- 그러나 국내 유사 앱은 전부 콜드스타트를 넘지 못하고 소멸했다 (모카콩 서버 중단, Coffice 리뷰 26개 등).
- 가장 큰 리스크 3가지: **데이터 신선도 유지 비용**, **크라우드소싱 콜드스타트**, **네이버/카카오 플랫폼 리스크**.

따라서 **앱을 만들지 않는다.** 한 상권을 수동 큐레이션한 정적 웹사이트로 수요를 먼저 검증한다.

---

## 2. 확정된 결정

| 항목 | 결정 | 의미 |
|---|---|---|
| **목표** | 수요 검증용 최소 사이트 | 4주 내 공개, 기능보다 데이터 품질과 공개 속도 우선 |
| **데이터 확보** | 직접 수동 조사 | 크라우드소싱 우회. 데이터 신뢰도가 유일한 차별점 |
| **지역 범위** | 한 상권 1곳 | 밀도 확보 우선. 상권 확정은 열린 질문 (5-1) |
| **백엔드** | 없음 — 정적 데이터 파일 | `cafes.json` 단일 파일. 계정·DB·쓰기 API 없음 |

파생 결정:

- 웨이팅리스트와 정보 정정 제보는 외부 폼(Tally/구글폼) 임베드로 처리한다. 백엔드를 만들지 않기 위한 선택.
- 지도는 카카오맵 JS SDK를 사용한다 (국내 사용자 친숙도 + 무료 티어).
- 배포는 정적 호스팅.

## 3. 이번 구현 범위 (In scope)

### 3.1 상권 1곳의 큐레이션 지도 + 리스트

- 지도 뷰(카카오맵 JS SDK)와 리스트 뷰 전환/병렬 배치
- 카페 30~100곳, 마커 클릭 → 상세 패널
- **상세에는 `last_verified`(언제 확인)와 `verify_method`(어떻게 확인)를 항상 노출한다.**
  네이버·카카오·블로그 대비 방어 가능한 유일한 차별점이므로, 부가 정보가 아닌 1급 UI 요소로 다룬다.

### 3.2 작업 특화 필터 — 기존 지도에 없는 것만

- 콘센트 등급: 많음 / 일부 좌석 / 거의 없음
- 카공 정책: 자유 / 시간제한 / 노스터디존 / 주말만 제한
- 소음: 조용함 / 적당한 백색소음 / 시끄러움
- 1인석·넓은 테이블 유무
- 지금 영업 중 / 22시 이후 영업
- 필터 조합은 URL 쿼리에 반영 → 공유 가능한 링크(= 공유 지표 측정 수단)

### 3.3 큐레이션 테마 링크 3~5개

"밤 10시 넘어서도 할 수 있는 곳", "화상회의 가능한 조용한 곳", "콘센트 확실한 곳" 등.
커뮤니티 배포 시 개별 링크가 곧 유입 실험 단위가 된다.

### 3.4 웨이팅리스트 + 정보 정정 제보 (백엔드 없이)

- 외부 폼 임베드
- "이 정보 틀렸어요" 버튼도 동일 폼 → 자발적 제보율(콜드스타트 가정) 측정 겸용

### 3.5 데이터 신선도 운영 장치

- 데이터는 `cafes.json` 단일 파일 (스키마: `docs/data-schema.md`)
- 각 항목에 `last_verified`, `verify_method`, `source_note`
- **90일 지난 항목은 UI에서 "정보 오래됨" 배지 자동 표시**
  → 2단계 "데이터 부패율 측정"을 별도 작업 없이 수행하기 위한 준비

### 3.6 계측

- 방문 / 필터 사용 / 상세 열람 / 공유 / 폼 제출을 최소 이벤트로 수집
- **판정 기준이 지표인 프로젝트이므로 계측은 옵션이 아니라 필수 범위다.**

## 4. 범위 밖 (Out of scope)

| 미루는 것 | 이유 |
|---|---|
| 로그인·계정 | 검증 단계에서 얻는 정보 대비 구현·유지비가 큼 |
| 사용자 리뷰/평점/사진 업로드 | 콜드스타트 실패의 전형. 제보 폼으로 의향만 먼저 측정 |
| 실시간 혼잡도, 실측 와이파이 속도 | 국내외 선례가 전부 마케팅 문구에 그침. 데이터 확보 수단 없음 |
| 즐겨찾기 서버 동기화 | 필요하면 localStorage로 충분 |
| 사장님 등록·B2B·제휴 | 사장 태도 가정이 미검증. 역풍 리스크 → 인터뷰 먼저 |
| 네이티브 앱 | "앱 설치를 유발할 만큼 페인이 크다"가 가장 의심스러운 가정 |
| 상권 확장 / 전국 | 밀도가 유일한 초기 가치. 확장은 1곳이 통한 뒤 |
| 자유 텍스트 검색창 | 100곳 규모에선 필터가 우월하고, 없는 데이터를 기대하게 만듦 |
| 예약·멤버십 수익화 | 3단계 이후 |

## 5. 열린 질문 — 사용자 확인 필요

> 아래는 구현 전에 사용자가 직접 결정해야 하는 항목이다. 담당: 사용자.

### 5-1. 어느 상권인지 확정 (**블로커**)

판단 기준 3가지:
1. 본인이 반복 방문 가능한 거리인가 (재조사 비용 = 프로젝트 지속성)
2. 노트북 작업 카페가 50곳 이상 실재하는가
3. 유입시킬 커뮤니티가 그 지역에 있는가

셋 다 애매하면 본인 생활권을 택한다.

### 5-2. 조사 비용을 실제로 감당할 수 있는지

- 직접 방문 1곳 = 음료값 + 30~40분
- 50곳 기준 **약 25~35시간, 25~40만원**

이 숫자를 보고도 진행할지, 아니면 "★ 항목만 방문 조사 / 나머지는 온라인 교차확인"으로 줄일지 결정.
여기서 타협하면 유일한 차별점이 사라지므로, **카페 수를 30곳으로 줄이고 품질을 지키는 쪽**을 권장.

### 5-3. "노스터디존" 표기의 리스크

사실과 다르게 표기하면 실제 매장에 영업 피해가 발생한다. 공개 전에 정할 것:
- 표기 근거 기준
- 정정 요청 접수 경로
- 사장 항의 시 삭제 여부

권장 원칙: **매장 게시물·직원 확인 두 가지 외에는 정책 필드를 비워둔다.**

### 5-4. 검증 성공 기준의 구체적 숫자와 유입 경로

"웨이팅리스트 전환율 두 자릿수"는 트래픽이 있어야 의미가 있다. **공개 전에** 적어둘 것:
- 4주 안에 어디에 뿌릴지 (에브리타임 / 스레드 / 개발자 커뮤니티 / 지역 커뮤니티)
- 몇 명 방문·몇 명 등록이면 계속인지

사후에 정하면 무조건 "가능성 있어 보인다"로 결론난다.

### 5-5. 카카오 개발자 계정과 도메인

지도 SDK는 앱 키 발급 + 도메인 등록이 필요하다. 도메인 구매 여부를 먼저 정해야 배포 시점이 잡힌다.

### 5-6. 리뷰·블로그 텍스트를 데이터 소스로 쓸 경우의 약관

직접 방문만 하면 무관. 5-2에서 "온라인 교차확인"으로 타협한다면 크롤링이 아닌 수동 열람 범위로 제한할 것.

### 5-7. 3개월 뒤 재확인을 실제로 할 의사가 있는지

데이터 부패율 측정은 이 프로젝트의 핵심 학습이다. 재조사를 안 하면 1단계 결과만으로는 아무것도 판정되지 않는다.
재조사 의사가 없다면 처음부터 목표를 "포트폴리오"로 바꾸는 게 정직하다.

## 6. 판정 기준

### 계속 (Go)
- 4주 내 유기적 방문/저장/공유가 유의미하게 발생
- 웨이팅리스트 전환율이 두 자릿수(%)
- (2단계) 사용자 제보가 자발적으로 발생

### 중단 (Kill)
- 네이버 또는 카카오가 콘센트/카공 필터를 정식 출시 → 즉시 재평가
- 3개월간 유지비가 성장을 초과하고 자발적 제보가 없음
- 순수 소비만 발생하고 제보 전환이 0 → 콜드스타트 실패로 간주
